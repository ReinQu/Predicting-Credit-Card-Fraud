# Kaggle 表格赛 Pipeline

> 从 s6e11 这个项目提炼出的通用流程。每个阶段都写明**做什么、为什么、产物、通过标准**。
> 核心原则：**每一阶段都有通过标准，不通过就不进入下一阶段。** 绝大多数翻车都来自跳过某一步。
>
> **可执行版本已封装为 skill**：`.claude/skills/kaggle-pipeline/SKILL.md`
> 与本文的区别：skill 里的噪声阈值改成"自己实测"而非照抄 0.0003，加了数据形态路由表和「反教条条款」。本文保留本项目的真实数字，作为案例对照。

---

## 总览

| # | 阶段 | 一句话目的 | 产物 | 通过标准 |
|---|---|---|---|---|
| 1 | 拿数据 | 文件齐不齐 | `data_manifest.md` | 行数/列数/大小与官方一致 |
| 2 | EDA | 建模的隐含假设成不成立 | `eda_report.md` | 分布、目标、泄漏三问有答案 |
| 3 | 验证设计 | CV 能不能代替 LB | 折索引 | 划分方式与 test 的生成方式一致 |
| 4 | 基线 | 有一个"地板分" | `cv_<model>.json` | 跑通 + 拿到 OOF AUC |
| 5 | 提交校准 | CV 值不值得信 | `submissions.md` | \|CV − LB\| < 0.001 |
| 6 | **噪声标尺** | 知道多小的改进是噪声 | 一个数字 | 得到种子间波动量级 |
| 7 | 瓶颈诊断 | 该往哪个方向使劲 | `tune_params.json` | 互斥假设有结论 |
| 8 | 特征工程 | 有没有新信息 | `feature_batches.json` | 每批 Δ 明确 |
| 9 | 特征消融 | 该删什么 | `feature_ablation.json` | 每列边际贡献 |
| 10 | 集成 | 模型多样性够不够 | `ensemble.json` | 相关性 < 0.98 |
| 11 | 停止判断 | 还值不值得投入 | `final_summary.md` | 三条证据一致 |

## 阶段 1：拿数据

**做什么**：`kaggle competitions files` 看清单 → `download --unzip` → 核对文件名/数量/大小/行数。

**为什么**：下载中断会留下残缺文件，而残缺文件不会立刻报错，只会在后面几个小时里表现为"分数莫名其妙"。**先核对，比事后排查便宜 100 倍。**

**通过标准**：
- 本地文件与 `competitions files` 输出一一对应
- `train` / `test` / `sample_submission` 齐全
- 行数写进 `data_manifest.md`，后续所有实验以它为准

**本项目实例**：train 699,960 行；test 299,984 行；三文件共 148 MB。

---

## 阶段 2：EDA

**做什么**：按"假设 → 统计量"的对照表逐项检验。

| 建模隐含假设 | 检验方法 | 通过则意味着 |
|---|---|---|
| train/test 同分布 | 逐列均值差 ÷ 合并标准差（SMD）、类别 TV 距离 | CV 能代表线上表现 |
| 每行独立 | 查完全重复行 | 不需要 GroupKFold |
| 缺失随机 | 查缺失率 | 不用做缺失填充策略 |
| 特征与目标有关 | 单特征 AUC / 相关系数 | 知道信号在哪 |
| ID 不携带信息 | ID 与目标的相关性、ID 分段后正类率 | 可用随机切分 |
| 目标分布稳定 | 正类率、分位数 | 不受时间漂移影响 |

**为什么**：EDA 不是画画，是**在建模前逐个验证建模的隐含假设**。哪一条不成立，后面的验证方案就得改。

**通过标准**：三问有答案——数据长什么样、哪里有坑、下一步造什么特征。

**关键判据**：
- SMD < 0.1：同分布
- 单特征 AUC = 0.5：该列单独无用（**但不能据此删列**，见阶段 9）
- ID 分段正类率平坦：无时间结构 → 用 `StratifiedKFold`

**本项目实例**：SMD 最大 0.0052、TV 最大 0.0023 → 同分布；ID 十分位正类率 1.59%–1.73% 平坦 → 随机切分可用。

---

## 阶段 3：验证设计

**做什么**：确定切分方式和指标复现。

| 数据形态 | 用什么 |
|---|---|
| 行独立同分布 | `StratifiedKFold`（分类）/ `KFold`（回归），5 折 |
| 同一实体多行 | `GroupKFold` / `StratifiedGroupKFold` |
| 时间序列 | `TimeSeriesSplit` 或按时间切 |
| 类别极不平衡 | `StratifiedKFold` + 关注 PR-AUC |

**为什么**：**本地验证必须模拟 test 的划分方式。** 否则调参调的是幻觉——CV 涨了，线上不动，甚至反跌。

**通过标准**：
- 指标用官方公式，在**完整 OOF** 上算一次，而不是把各折分数平均
- 切分只做一次，固定种子，全程复用

**本项目实例**：5 折 `StratifiedKFold(shuffle=True, random_state=42)`，指标 `roc_auc_score(y, oof)`。

---

## 阶段 4：基线

**做什么**：LightGBM + 原始特征，不重采样、不做复杂预处理。

**为什么**：先要一个**可信的地板分**，后面所有改进都跟它比。基线越简单，越容易判断改进来自哪里。

**通过标准**：
- 跑通 → 拿到 OOF AUC
- 每折 AUC 与折间 std 都记录下来
- OOF 预测落盘（后续融合、消融都复用它）

**本项目实例**：OOF **0.945650**，折间 std 0.0032，耗时 65 秒。

---

## 阶段 5：提交校准

**做什么**：用基线预测生成 `submission.csv` → 跑完格式断言 → 提交 1 次 → 比较 CV 与 LB。

**为什么**：这是**整个项目的信任基础**。提交前你无法确定：有没有泄漏（CV 虚高）、有没有漂移（CV 虚低）、提交流程有没有 bug。一次提交同时排除这三种可能。

**通过标准**：**|CV − LB| < 0.001** → CV 可作为后续所有决策的依据

**格式断言清单**：
- 列名与列顺序与 `sample_submission` 一致
- 行数一致、id 集合一致、id 无重复
- 预测值无 NaN、值域合法（概率在 [0,1]）
- 预测均值接近训练集正类率（本项目 0.01640 vs 0.01670）

**本项目实例**：CV 0.945650 → LB 0.94637，差 +0.00072 ✅

**注意**：public LB 只用 test 的一个子集，抽样噪声可达 ±0.0005。所以 CV–LB 偏移量**会变**（本项目两次分别 +0.00072 和 +0.00027），这不影响 CV 的可信度，但**不能把 CV 当 LB 的精确预测**。

---

## 阶段 6：噪声标尺（最容易跳过、也最关键）

**做什么**：同一配置、只换折种子（或模型种子），重跑 2 次，记录 OOF 差异。

**为什么**：**没有这个数字，你无法判断任何改进是真是假。** 后面每一个 Δ 都要拿它做尺子。

**通过标准**：得到一个明确的量级，写进实验日志。

**本项目实例**：换种子 OOF 只差 **0.00014–0.00016**。

由此确立判定规则：

| Δ 大小 | 判定 |
|---|---|
| < 0.0003 | 噪声，不可信，不下结论 |
| 0.0003–0.001 | 有个种子确认才可信 |
| > 0.001 | 可直接采信 |

**后续效果**：调参 +0.00115 判为真实（噪声的 7 倍）；消融 +0.00025 判为"未确证"。**同一个数字，有没有尺子，结论完全相反。**

---

## 阶段 7：瓶颈诊断（调参）

**做什么**：设计 **3 组互斥假设**，而不是盲扫网格。

| 组 | 参数方向 | 回答的问题 |
|---|---|---|
| A 容量+ | `lr↓`、`num_leaves↑`、`min_child_samples↓` | 模型是否欠拟合？ |
| B 正则+ | `num_leaves↓`、`min_child_samples↑`、`reg_lambda↑`、`colsample↓` | 模型是否过拟合？ |
| C 加权 | `scale_pos_weight` / 重采样 | 不平衡是否值得处理？ |

**为什么**：**调参一次 65 秒，特征工程一次 40 秒，但它们回答的是不同问题。** 先用便宜的手段定位瓶颈，避免在错误方向上花几小时。A 和 B 是对立方向，必须分开测。

**前置知识**：对 AUC 这类排序指标，**类加权和重采样通常无用甚至有害**（本项目 −0.0019）。理论依据：AUC 只看排序，重加权改变的是优化目标而非排序质量。

**通过标准**：三组各自有明确结论 → 得到"该往哪走"的方向。

**方向确定后的收敛判断**：看边际收益。
- 本项目：baseline → B_reg(+0.00094) → B_plus(+0.00021)，**收益掉到 1/4 就停**

**注意**：树模型不需要这些操作——标准化、`log1p`、分箱、PCA 都不改变分裂点位置，一律不做。

---

## 阶段 8：特征工程

**做什么**：按类别分批造特征，**每批单独加入、单独评估**。

| 批次类型 | 例子 | 预期 |
|---|---|---|
| 比值 | `amount / balance` | 把绝对量变相对量 |
| 聚合 | 多个布尔标志求和 | 把稀疏信号合成密度 |
| 交互 | `distance × is_foreign` | 喂给模型的显式组合 |
| 类别组合 | `cat_a + "_" + cat_b` | 交叉类别 |

**为什么分批**：一次性加 13 个特征，涨了不知道是谁的功劳，跌了不知道删哪个。

**通过标准**：每批一个明确的 Δ，并给出判定。

**本项目实例**：**4 批全部失败**（−0.00029 / −0.00005 / −0.00006 / −0.00075）。

**为什么失败（可迁移的教训）**：
- GBDT **本来就擅长组合特征**，人工造的求和/乘积它早就会了（B2/B3 打平即证据）
- 比值类特征往往**基数极高**（`amt_bal_ratio` 有 68 万取值），给模型提供了记住单行的机会
- 类别组合会让每类样本变稀疏（60 类摊 1.17 万正例 = 每类 195 个）

---

## 阶段 9：特征消融

**做什么**：留一法——每次只删一列，跑一次看 Δ。

**为什么**：**单特征 AUC ≈ 0.5 不等于该列没用。** 本项目实测：`distance_from_home_km` 单特征 AUC 0.504，特征重要性排第 7。它靠的是交互。**只能靠消融测边际贡献，不能靠单特征指标删列。**

**注意**：
- 单列 Δ 常落在噪声内，但**多列合起来的累积效应会显形**（本项目单删全部 <0.0003，全删 8 列 +0.00039）
- 累积效应也要跨种子验证（本项目第二次只 +0.00011 → 判为"未确证"）

**通过标准**：得到每列的边际贡献 + 一个"删列后"的配置，并标注可信度。

---

## 阶段 10：集成

**做什么**：训练多个"犯错方式不同"的模型 → 算 OOF 相关性 → 比较等权 / Rank 平均 / 优化权重。

**为什么**：集成的原理是**不同模型犯不同的错，平均能抵消**。若相关性 ≥ 0.98，它们犯的错几乎一样，平均等于没平均。

**通过标准**：
- **先看相关性，再看分数。** 相关性 0.99 的模型加进来基本无效
- 优化权重若形态极端（某模型 0.9+，某模型归零），判为 OOF 过拟合，退回等权

**本项目实例**：
- 相关性全部 ≥ 0.98 → 集成只涨 +0.00021（预期 +0.0005~0.0015）
- 优化权重 `{lgbm42: 0.46, xgb: 0.00}` 形态极端，且只比等权高 0.000025 → **弃用**
- XGBoost 单模型最弱 + 相关性最高 → **剔除**（加它反而掉分）

**教训**：**模型多样性比模型数量重要。**

---

## 阶段 11：停止判断

**做什么**：当改进连续几轮低于噪声线，做一次结构性探测，然后决定停不停。

**三条独立证据**（任一成立即可考虑停止，三条都成立则果断停）：

1. **没有确定性公式可反推**：用其余列预测每个数值列，R² 是否接近 1
2. **标签不是确定函数**：按离散特征分组，看"全 1 组"的数量（**不要看"全 0 组"**，正类率低时全 0 是必然的）
3. **加容量 / 加特征 / 加模型全部无效或有害**

**本项目实例**：R² 最高 0.639；27,635 个大组里"全 1 组" = 0；前 10 组实验证明加什么都无效。→ **主动停止。**

**停止不等于失败**：投入产出比翻转时就该停。此时应该做的是把流程和否定结论整理成文档。

## 适用边界（重要）

本文混着两层东西，迁移时**只能搬左边**：

| 能迁移（结构性，跟数据无关） | 不能迁移（条件性，换个赛就反了） |
|---|---|
| 先验证 CV 再看 LB | "树模型不需要标准化" |
| 先测噪声标尺再判改进 | "类加权对 AUC 有害" |
| 互斥假设 > 网格搜索 | "特征工程无效" |
| 否定结果必须记录 | "集成收益一定很小" |
| 按成本排序定位瓶颈 | "该用 16 列特征" |

右边每一条的具体成立条件：

| 结论 | 成立条件 | 条件失效时 |
|---|---|---|
| 类加权 / 重采样有害 | 指标是 **AUC**（只看排序） | LogLoss / F1 / 召回导向 → 必须重测，往往有用 |
| 树模型不需标准化 / log1p / 分箱 | 模型是**树模型** | 线性模型 / 神经网络 / KNN → 必须要 |
| 人工特征无效 | 信号**加性** + GBDT + 大样本 | 文本 / 时序聚合 / 多表 join → 特征是主要来源 |
| 集成收益小 | 相关性 **≥ 0.98** | 小数据集 / 异构模型族 → 收益可大得多 |
| `StratifiedKFold` | 行**独立同分布**、无时间结构 | 分组 / 时序 → `GroupKFold` / `TimeSeriesSplit` |
| 16 列最优 | **仅此数据集** | 新比赛 → 从原始列重新消融 |
| 噪声标尺 ≈ 0.00015 | 70 万行 + AUC | 数据量或指标一变 → 重测 |

### 开赛前的差异检查

用这套流程开新比赛时，先写 50 个字：

```
数据形态：
官方指标：
test 的划分方式：
和 s6e11 的关键差异：
```

作用是**强制把注意力放在差异上，而不是相似上**。

### 反教条条款

1. EDA 发现任一前提与 s6e11 不同 → **先改流程再开跑**，不要硬套
2. 某阶段通过标准明显不适用 → 写明理由后跳过，不要为走完流程而走
3. 改动违反本文建议但你有机制解释 → 做，记录结果。**机制比清单可靠**
4. 全流程走完分数还在涨 → 说明有一步判断太保守，回头找

## 通用陷阱清单

| 陷阱 | 症状 | 对策 |
|---|---|---|
| 早停用验证折 | OOF 略乐观（本项目估计 <0.001） | 记录在案；严格对比时改固定轮数或内层验证 |
| 拿 public LB 调参 | 线上 public 高、private 崩 | 只信 CV，LB 仅用于校准 |
| 单特征 AUC 删列 | 删掉了高重要性列 | 用消融，不用单特征指标 |
| 把噪声当改进 | 反复在 0.0001 上折腾 | 阶段 6 先测噪声标尺 |
| 一次性加一堆特征 | 不知道谁有用 | 分批，每批 3–5 个 |
| 集成不查相关性 | 堆了 5 个模型只涨 0.0002 | 先看 Spearman |
| 优化权重当真 | OOF 最高但线上不兑现 | 看权重形态是否极端 |
| 不平衡就重采样 | AUC 反而下降 | 排序指标通常不需要 |
| 对树模型做标准化/分箱 | 白费时间 | 单调变换不改变分裂点 |

## 记录规范

每次实验都要落盘，否则一周后无法复现结论。

```
reports/
├── data_manifest.md       数据清单
├── eda_report.md          EDA 结论
├── cv_log.md              实验表：改动 / OOF AUC / 折间 std / 判定
├── submissions.md         提交表：文件 / CV / LB / 差值 / 结论
├── final_summary.md       复盘
└── <exp>.json             每组实验的完整参数与逐折结果
```

`cv_log.md` 一行一次实验，**必须包含"判定"列**——记录结论，而不只是数字。
